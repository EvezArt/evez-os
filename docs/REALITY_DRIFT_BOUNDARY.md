# Reality Drift Boundary

EVEZ-OS treats reality status as runtime metadata, not personality.

The operator and project are separate:

```text
Steven Crawford-Maggard  -> operator
EVEZ                    -> project/system
agent instances         -> software actors
Event Spine             -> evidence record
Reality Gate             -> action boundary
```

Every agent-produced statement that can influence an external mutation should be
classified before the mutation.

Required state fields:

- claim class
- evidence references
- event references
- reproducibility
- requested effect
- effective effect
- narrative flag
- gate decision

The runtime must preserve the distinction:

```text
DECLARED != EFFECTIVE
CLAIM != EVIDENCE
CAPABILITY != AUTHORITY
NARRATIVE != FACT
SILENCE != SUPPRESSION
FAILURE != INTENT
```

The runtime interrupt is:

> DRIFT DETECTED
> Claim exceeds evidence.
> Return to observable state.
> What happened?
> What changed?
> What is recorded?
> What remains unknown?
> What can be reproduced?

The purpose is not to suppress interpretation. Interpretation can be stored as
interpretation. The purpose is to stop an interpretation from silently becoming
authorization, accounting, legal fact, or operational truth.
