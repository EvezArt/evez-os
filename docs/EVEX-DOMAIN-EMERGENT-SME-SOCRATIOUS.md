# EVEX Domain-Emergent SME-Adaptive Socratious Runtime

## Purpose

The Domain-Emergent SME-Adaptive Socratious runtime (DESA-S) is a reference controller for problem settings where the runtime is not given a fixed domain ontology or a trusted expert model in advance.

It combines four capabilities:

1. temporary domain induction from observations;
2. evidence-bound subject-matter-expertise profiling from demonstrated outcomes;
3. adaptive Socratic question selection;
4. recursive self-witnessing of the target-selection process.

The runtime is deliberately conservative. It does not claim consciousness, general intelligence, or truth discovery. A correction proposal is not a verified fact, and an inferred SME region is not a credential.

## Runtime loop

UNKNOWN PROBLEM -> OBSERVE -> ENTITY ECC -> DOMAIN INDUCTION -> SME INDUCTION -> SELF-WITNESSING TARGETER -> ADAPTIVE QUESTION -> NEW OBSERVATION -> repeat.

The reference selection policy is explicit and replayable. It prioritizes active contradiction and entity error, then unresolved domain structure, adaptive SME uncertainty, question-policy calibration, targeter self-state, and ordinary observations.

## Entity error-correction code

Semantic entities are treated as evidence-bound codewords with identity, attributes, relationships, observations, and provenance.

Identity collision, attribute conflict, contradiction, and provenance gaps produce an error syndrome. The runtime then generates correction candidates.

A correction remains PROPOSED or UNKNOWN until adequate evidence exists. Majority observation count alone does not promote UNKNOWN to VERIFIED.

## SME induction

The SME profile is a bounded runtime estimate, not a credential. It accumulates:

- successful demonstrations;
- failures;
- region-level competence estimates;
- calibration;
- unresolved scope.

This gives the adaptation layer a failure surface instead of a single confidence scalar.

## Self-witnessing targeter

The targeter is itself a member of the candidate target space.

Candidate classes include entity, evidence, contradiction, domain, SME, question policy, witness, and targeter.

Every selection receipt records:

- complete target ranking;
- selected target;
- rejected targets;
- selection policy;
- observer state before and after selection;
- self-observation confirming whether the targeter was in its own candidate space;
- integrity hash.

Core invariant:

> No witness is exempt from witnessing.

The recursion is an auditable control/data path. It is not evidence of subjective awareness.

## Opaque-domain adaptation

The regression fixture uses opaque terms such as zorq, nyx, and phase-b. No domain adapter is supplied for these terms. The test therefore exercises construction of a temporary domain representation from observations rather than dispatch through a hard-coded domain plugin.

This is an engineering proxy for an unseen domain, not evidence of universal zero-shot competence.

## EVEX integration

DESA-S can emit state and selection receipts carried inside the existing EVEX accountable state-transition profile.

The interoperability boundary remains:

READ -> VALIDATE -> VERIFY -> CLASSIFY -> AUTHORIZE -> ACT -> EMIT.

DESA-S supplies domain/question/target/witness state. It does not manufacture authority.

## Falsifiable research program

Evaluate the runtime on held-out domains with metrics including:

- domain induction accuracy;
- entity corruption detection;
- false-correction rate;
- unsupported epistemic-promotion rate;
- information gain per question;
- SME calibration;
- contradiction resolution rate;
- self-target coverage;
- receipt reproducibility.

The research question is whether this explicit epistemic controller improves adaptation while reducing silent error and unsupported certainty compared with answer-only orchestration.
