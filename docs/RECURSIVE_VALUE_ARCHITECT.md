# EVEZ Recursive Value Architect

The Recursive Value Architect turns the luxury recursive-value prompt into a bounded runtime that can scan, decompose, synthesize, compare, and package value opportunities without pretending that proposals are facts or that authorization is execution.

## Runtime chain

`OBSERVE -> EXTRACT -> NORMALIZE -> DECOMPOSE -> MODEL -> CALCULATE -> REVERSE_ENGINEER -> GENERATE -> TEST -> FALSIFY -> FRONTIER -> ACQUISITION_PLAN -> TRANSFORM -> PACKAGE -> WITNESS -> RECIRCULATE`

The engine integrates three existing EVEZ-OS layers:

1. `evez_unlock.py` calculates capability state.
2. `evez_architect.py` supplies self-discovery and polycentric architecture proposals.
3. `evez_toroid.py` supplies bounded multi-pole synthesis.

The new runtime adds a value graph, lawful acquisition filtering, reverse-engineering plans, Pareto frontier selection, generated artifact inventory, authority gates, and a chained value ledger.

## Evidence boundary

The runtime treats these as distinct:

`DECLARED != CALCULATED != EFFECTIVE`

`CLAIMED != MEASURED != REPLICATED != EXPLAINED`

`PROVENANCE != TRUTH`

`UNKNOWN != permission`

`PROPOSED != VERIFIED`

`acquisition plan != acquisition execution`

`proposal != activation`

Numeric objective values are read from explicit inputs only. Missing values remain `UNKNOWN`. The runtime does not fabricate a performance number merely because an optimization formula would be convenient.

## Legitimate acquisition boundary

Acquisition routes are executable-plan candidates only when their state is `PUBLIC`, `LICENSED`, or `AUTHORIZED`. An authorization-required route is still blocked unless its authorization state is explicitly `AUTHORIZED`.

Reverse-engineering is treated as observable decomposition of assets the operator is permitted to inspect. The runtime does not implement credential theft, access-control bypass, covert collection, unauthorized copying, or exploit execution.

## Loot inventory

"Loot" is a planning term for reusable value-producing artifacts generated by the runtime. Each inventory entry is marked `PROPOSED` until independently validated.

Default artifact classes are:

- normalized value graph
- research compression packet
- capability unlock map
- reverse-engineering plan
- lawful acquisition plan
- adversarial test suite

These are plans and artifacts, not proof of successful commercialization or acquisition.

## Mobile usage

From a checked-out repository:

```bash
python mobile/evez_value_architect.py mobile/value-context.example.json --generations 3 --toroidal-generations 2 --poles 8 --output value-plan.json --ledger value-ledger.jsonl
```

Scan only:

```bash
python mobile/evez_value_architect.py mobile/value-context.example.json --mode scan
```

From `evezctl`:

```bash
evezctl value-scan mobile/value-context.example.json
evezctl value-evolve mobile/value-context.example.json --generations 3 --toroidal-generations 2 --poles 8 --output value-plan.json --ledger value-ledger.jsonl
```

## Recursive optimization model

A generation may discover that its current highest-value move is not a product at all. It may be:

- unlocking a blocked capability,
- producing a better measurement,
- reducing unknowns,
- preserving contradictory evidence,
- acquiring a lawful public source,
- converting a source into a reusable test harness,
- composing several verified artifacts into a higher-order artifact,
- or improving the generator so later generations have a larger valid search space.

The recursion is bounded by `--generations` and `--toroidal-generations`. "Infinite" in the design language means resumable continuation across bounded cycles, not an unbounded process that ignores resource or safety limits.

## Output

The result contains:

- value graph
- calculated capability states
- system discovery
- polycentric frontier
- toroidal frontier
- reverse-engineering observations
- generated candidates
- Pareto frontier
- lawful acquisition routes
- proposed loot inventory
- authority decisions
- chained ledger events
- a final SHA-256 architecture digest

Activation remains outside this runtime. A separate authority-controlled operation must promote a validated proposal.
