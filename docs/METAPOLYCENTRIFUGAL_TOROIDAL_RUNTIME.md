# Metapolycentrifugal Toroidal Runtime

This layer treats architecture as a circulating field rather than a single hierarchy.

DISCOVER -> MULTI-POLE GENERATE -> FALSIFY -> CIRCULATE -> MIRACULATE -> NEXT GENERATION

The torus contains multiple architectural poles with distinct objectives. Each pole participates in local generation and cross-pole exchange. Opposite poles are cross-linked so local optimization cannot become the entire architecture.

Miraculation is the name for a bounded synthesis event that combines multiple independently surviving parent candidates into a new candidate lineage. It is deterministic and hash-addressed.

The runtime measures:

- circulation: phase-driven movement around the torus
- centrifugal field: structural outward pressure from the poles
- epistemic friction: unresolved or blocked capability state
- novelty: distance from the parent set
- stability: resistance to epistemic friction
- contradiction retention: explicit preservation of disagreement

Safety boundary:

PROPOSAL ONLY. The generator cannot activate its own inventions. UNKNOWN never becomes permission merely because several poles agree.

Termux:

python ~/evez-os/mobile/evez_toroid.py ~/evez-os/mobile/architecture-context.example.json --generations 8 --poles 8

The resulting toroidal architecture is identified by a SHA-256 digest.
