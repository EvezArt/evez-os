# EVEZ Self Architecture Runtime\n\nThe self-architecture layer closes the loop:\n\nDISCOVER -> INVENT -> SIMULATE -> FALSIFY -> RANK -> PROPOSE\n\nDiscovery inspects repository topology, runtime context, capability calculations, and current architecture holes.\n\nInvention produces deterministic architecture candidates by mutating a small graph grammar. Candidates include nodes, edges, required capabilities, invariants, and adversarial tests.\n\nEvaluation rejects broken graphs, missing safety boundaries, and insufficient capability readiness.\n\nEvolution produces a frontier of surviving candidates across generations. Every candidate retains its parent identifier and SHA-256 address.\n\nThe runtime stops at a proposal boundary. It may discover and invent architecture, but activation remains outside the invention engine and must pass the existing authorization controls.\n\nCore laws:\n- UNKNOWN is not permission.\n- A proposal is not an activation.\n- Claimed state is not measured state.\n- A candidate without a falsification stage is invalid.\n- Every generated graph must be replayable from canonical inputs.\n- Every promoted design must preserve provenance and rollback.\n\nTermux entry point:\npython ~/evez-os/mobile/evez_architect.py ~/architecture-context.json --generations 5\n\nUse the resulting JSON as the next architecture input. It contains the discovery digest, frontier, champion evaluation, and overall frontier digest.
